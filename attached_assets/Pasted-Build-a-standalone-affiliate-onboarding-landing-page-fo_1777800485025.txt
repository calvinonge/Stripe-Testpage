Build a standalone affiliate onboarding landing page for the campaign at:
https://pluvus.com/join/calvin-od8afn

This page replaces the default Pluvus-hosted join page. It uses the headless 
path of the Pluvus join API — name and email only, no PayPal collection. 
The affiliate's commissions track and accumulate normally. Payment info will 
be collected manually by the merchant later.

────────────────────────────────────────────────────────────
PAGE STRUCTURE
────────────────────────────────────────────────────────────
Three states rendered in place:

  STATE 1 — Form (default)
  STATE 2 — Loading (POST in flight)
  STATE 3 — Success
  STATE 3b — Pending (approval required)
  STATE 4 — Error (inline, form stays visible)

────────────────────────────────────────────────────────────
STATE 1: FORM
────────────────────────────────────────────────────────────
Single-column centered form, max-width 480px.

Header section:
- Merchant name: "Calvin's test"
- Headline: "Join the Calvin Affiliate Program"
- Commission callout: "Earn 20% commission on the first sale you refer"
- Short description: "Sign up in seconds. You'll get a unique tracking link 
  and a promo code to share with your audience right away."

Form fields (in this order):
1. Full Name
   - Input type: text
   - Placeholder: "Your full name"
   - Required: yes
   - Validation: must not be blank or whitespace-only

2. Email Address
   - Input type: email
   - Placeholder: "you@example.com"
   - Required: yes
   - Client-side validation: standard email format before submitting
   - Rule: trimmed and lowercased before sending

Submit button:
- Label: "Join Program"
- Full width
- Disabled and shows a spinner while the POST is in flight

────────────────────────────────────────────────────────────
API CALL (fires on valid form submit)
────────────────────────────────────────────────────────────
POST https://pluvus.com/api/join/calvin-od8afn
Content-Type: application/json

Request body — send ONLY these two fields:
{
  "name":  "<trimmed value from field 1>",
  "email": "<trimmed + lowercased value from field 2>"
}

CRITICAL: Do NOT include paymentMethod or paymentInfo in the request body 
at all — not even as null or empty string. If paymentMethod is present in 
the body with any value other than "paypal", the API returns a 400 error. 
If paymentMethod is "paypal" but paymentInfo is missing, the API returns 
a 400 error. The only safe headless path is to omit both fields entirely.

────────────────────────────────────────────────────────────
HANDLING THE RESPONSE
────────────────────────────────────────────────────────────
Success (HTTP 200):

  Case A — Instant activation:
    response.success === true AND response.affiliate.trackingLink is present
    → Show STATE 3 (Success screen)

  Case B — Pending approval:
    response.status === "pending"
    → Show STATE 3b (Pending screen)

Error (HTTP 4xx or 5xx):
    response.error will be a string. Map it:

    "Email is required"
      → "Please enter your email address."

    "Name is required"
      → "Please enter your name."

    "Invalid email format"
      → "Please enter a valid email address."

    "This campaign is not accepting new affiliates"
      → "This program is currently closed to new applications."

    "This email is already registered for this campaign..."
      → "You're already registered. Check your inbox for your tracking link."

    Any other error
      → Show the raw response.error string

    Show inline above the submit button. Do NOT clear the form.

HTTP 429:
    → "Too many attempts. Please wait a moment and try again."

Network failure:
    → "Something went wrong. Please check your connection and try again."

STATE 3: SUCCESS SCREEN
────────────────────────────────────────────────────────────

4. Tracking link box:

   - Label: "Your promo code"
   - Display: response.productAccess.promoCode (read-only)
   - Copy button: same behavior
   - Note: "Share this code with your audience. They get a discount and 
     you earn your commission."

6. Next steps:
   - "A welcome email has been sent to <email they entered> with 
     everything you need."
   - "Questions? Reach Calvin's test at stripetesting.replit.app"

Replace the form with:

────────────────────────────────────────────────────────────
VALIDATION (client-side, before any fetch)
────────────────────────────────────────────────────────────
- Name: not empty, not whitespace-only → show "Please enter your name."
- Email: passes /^[^\s@]+@[^\s@]+\.[^\s@]+$/ → show "Please enter a 
  valid email address."
- Trim all values before validating and before sending
- Show per-field inline errors on submit attempt. Do not clear valid fields.

────────────────────────────────────────────────────────────
IMPORTANT IMPLEMENTATION NOTES
────────────────────────────────────────────────────────────
- No auth headers, API key, or cookies required.
- CORS is fully open — this page can live on any domain.
- Do not re-fetch campaign data at runtime. All campaign info above is 
  already known and should be hardcoded into the UI.
- The two-field headless path (name + email only, no payment fields) is 
  intentional. The affiliate will still be fully tracked and their 
  commissions will accumulate. Payment details can be collected later 
  out-of-band by the merchant.
- The promo code in the success response comes from the Pluvus backend — 
  you do not need to generate or store it yourself.
- Rate limit is 500 requests/minute per IP. Not relevant for a human form.
