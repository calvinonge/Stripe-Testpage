Build a standalone affiliate onboarding landing page for the campaign at:
https://pluvus.com/join/calvin-od8afn

This page replaces the default Pluvus-hosted join page with a fully custom 
design on our own domain. It submits directly to the Pluvus API. No Pluvus 
account, session, or API key is required. CORS is fully open.

────────────────────────────────────────────────────────────
PAGE STRUCTURE
────────────────────────────────────────────────────────────
The page has three distinct states rendered in place (no page navigation):

  STATE 1 — Form (default)
  STATE 2 — Loading (while the POST is in flight)
  STATE 3 — Success (after a 200 response)
  STATE 3b — Pending (if response.status === "pending")
  STATE 4 — Error (inline, form stays visible)

────────────────────────────────────────────────────────────
STATE 1: FORM
────────────────────────────────────────────────────────────
Show a single-column centered form with a max-width of 480px. Include:

Header section:
- Merchant name: "Calvin's test"
- Campaign headline: "Join the Calvin Affiliate Program"
- Commission callout: "Earn 20% commission on the first sale you refer"
- Short description of what happens after joining (they get a unique 
  tracking link and a promo code to share)

Form fields (in this order):
1. Full Name
   - Input type: text
   - Placeholder: "Your full name"
   - Required: yes
   - Validation: must not be blank or whitespace-only

2. Email Address
   - Input type: email
   - Placeholder: "you@example.com"
   - Required: yes
   - Client-side validation: standard email format check before submitting
   - Rule: trimmed and lowercased before sending to the API

3. PayPal Email
   - Label: "PayPal Email (for commission payouts)"
   - Input type: email
   - Placeholder: "your-paypal@example.com"
   - Required: yes
   - Note below field: "This is where your 20% commission will be sent. 
     Can be different from your sign-up email."
   - Client-side validation: standard email format check

4. Confirm PayPal Email
   - Label: "Confirm PayPal Email"
   - Input type: email
   - Placeholder: "Confirm your PayPal email"
   - Required: yes
   - Validation: must exactly match field 3 before the form submits.
     Show an inline error "PayPal emails do not match" if they differ.
     Do not surface this error until the user attempts to submit.

Submit button:
- Label: "Join Program"
- Full width
- Disabled and shows a spinner while the POST is in flight

────────────────────────────────────────────────────────────
API CALL (fires on valid form submit)
────────────────────────────────────────────────────────────
POST https://pluvus.com/api/join/calvin-od8afn
Content-Type: application/json

Request body:
{
  "name":          "<trimmed value from field 1>",
  "email":         "<trimmed + lowercased value from field 2>",
  "paymentMethod": "paypal",
  "paymentInfo":   "<trimmed + lowercased value from field 3>"
}

Do NOT send paymentInfoConfirm to the API — that field is UI-only.
Do NOT send paymentMethod as anything other than the exact string "paypal".
Do NOT send paymentInfo as an empty string — if field 3 is empty the form 
should block submission before the fetch fires.

────────────────────────────────────────────────────────────
HANDLING THE RESPONSE
────────────────────────────────────────────────────────────
Success (HTTP 200):

  Case A — Instant activation (most common):
    response.success === true AND response.affiliate.trackingLink is present
    → Show STATE 3 (Success screen)

  Case B — Pending approval:
    response.status === "pending"
    → Show STATE 3b (Pending screen)

Error (HTTP 4xx or 5xx):
    response.error will be a string. Map it to a human-readable message:

    "Email is required"
      → "Please enter your email address."

    "Name is required"
      → "Please enter your name."

    "Invalid email format"
      → "Please enter a valid email address."

    "Payment information is required"
      → "Please enter your PayPal email."

    "Invalid PayPal email format"
      → "Please enter a valid PayPal email address."

    "This campaign is not accepting new affiliates"
      → "This program is currently closed to new applications."

    "This email is already registered for this campaign..."
      → "You're already registered. Check your inbox for your tracking link."

    Any other error
      → Show the raw response.error string

    Display error inline above the submit button. Do NOT clear the form.
    The affiliate should be able to fix their input and resubmit.

HTTP 429 (rate limit):
    → "Too many attempts. Please wait a moment and try again."

Network failure (fetch throws):
    → "Something went wrong. Please check your connection and try again."

────────────────────────────────────────────────────────────
VALIDATION RULES SUMMARY (client-side, before any fetch)
────────────────────────────────────────────────────────────
- Name: not empty, not whitespace-only
- Email: passes basic email regex (/^[^\s@]+@[^\s@]+\.[^\s@]+$/)
- PayPal email: passes same regex
- PayPal confirm: exactly matches PayPal email field (case-insensitive)
- If any check fails, show a per-field inline error and abort the fetch
- Trim all string values before validating and before sending

────────────────────────────────────────────────────────────
IMPORTANT IMPLEMENTATION NOTES
────────────────────────────────────────────────────────────
- No auth headers needed. No API key. No cookies required.
- The POST endpoint has CORS fully open (Access-Control-Allow-Origin: *),
  so this can be hosted on any domain and called directly from the browser.
- Do not call GET /api/join/calvin-od8afn at runtime — the campaign data 
  is already known and should be hardcoded.
- Do not store or log paymentInfo (the PayPal email) anywhere on your own 
  servers. It goes straight to the Pluvus API and is handled there.
- The page should work without JavaScript disabled fallback — this is an 
  interactive form, JS is required.
- Rate limit is 500 requests/minute per IP. This is never a concern for 
  a real user filling out a form.
