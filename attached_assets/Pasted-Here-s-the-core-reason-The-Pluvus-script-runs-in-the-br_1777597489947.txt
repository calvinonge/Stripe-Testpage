Here's the core reason:

The Pluvus script runs in the browser. It writes the pluvus_click_id into a browser cookie. That cookie lives on the user's device.

When the frontend calls their backend to create the Stripe session, that's a server-side process — the server has no visibility into what's in the user's browser. It can't reach into the browser and read a cookie. The only way the backend ever knows what click_id is in the browser is if the frontend explicitly passes it in the API request body.

So the gap is:

Browser cookie (pluvus_click_id) ←— script writes this
        ↓
Frontend must bridge this gap manually ← Step 2
        ↓
Backend receives it in request body
        ↓
Backend puts it in Stripe session metadata ← Step 3
        ↓
Stripe webhook → Pluvus reads it

If they used Stripe Payment Links (no custom backend), our script intercepts the checkout link click directly in the browser and handles it automatically — no step 2 needed. But because they have their own backend API that creates the session, the script has no way of knowing when or where that API call happens. The frontend has to do that bridge itself.

So step 2 isn't a Pluvus quirk — it's just the reality of how browsers and servers work.

It's needed for any merchant doing it this way — not just NeoBound. The pattern is what determines it, not the merchant.

Simple rule:

Integration type	Step 2 needed?
Custom backend creates Stripe session (like NeoBound)	Yes — frontend must pass the cookie
Shopify	No — script injects into cart automatically
Stripe Payment Links	No — script handles it via the thank-you page
Third-party checkout (client-side trackConversion)	No — script reads cookie directly on thank-you page
Any merchant who has their own backend API that creates the Stripe session will always need step 2. That's because the same problem exists for all of them — the script writes the cookie in the browser, the backend creates the session on the server, and those two things can't talk to each other unless the frontend bridges them.

NeoBound isn't a special case. If you onboard another merchant tomorrow who has the same architecture (frontend → their own backend → Stripe session), they'd need the exact same three steps.
